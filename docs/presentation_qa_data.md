## B. 기능적 질문 (10)

**B1. 4명이 동시에 개발하는데 데이터 형식은 어떻게 맞췄나요?**
첫 PR에서 모듈 간 데이터 형식(`contracts.py`), 엔진, 정답 테스트를 한 번에 올리고 담당별로 리뷰를 받았습니다. 이후 형식 변경은 기존 값을 바꾸지 않고 추가만 했고, 팀 합의 후 머지했습니다. (#1, #32, #38)

**B2. AI는 엔진 도구를 어떻게 아나요?**
엔진이 도구 목록과 입력 형식을 Gemini function calling용 스키마로 직접 만들어 줍니다. 도구를 추가하면 AI 쪽 선언이 자동으로 따라가서 둘이 어긋나지 않습니다. (#4)

**B3. 표를 붙일 때 숫자가 부풀지 않나요?**
예산은 업무 행에 붙이지 않고 프로젝트 표에서 한 번만 씁니다. 붙인 뒤 행 수(150)가 그대로인지 검사하고, ID가 중복되면 붙이지 않습니다. 잘못 붙이면 7.03억이 109.03억이 되는 것을 테스트로 고정했습니다. (#1, #17)

**B4. 비정상 파일은 어떻게 시험했나요?**
오류 샘플 8종을 만들었습니다. 빈 파일, 제목만 있는 파일, 컬럼 누락, 숫자 오류, ID 중복, cp949 인코딩, 지시문이 들어간 파일 등입니다. 파일마다 어떤 오류 안내가 나와야 하는지 테스트로 확인합니다. (#1, `data/errors/`)

**B5. 형식이 틀린 값은 행째 빼나요, 칸만 빼나요?**
처음에는 행째 뺐습니다. 공개 벤치마크의 승객 데이터에서 티켓 번호 칸 때문에 운임 평균이 34.65가 아니라 30.09로 틀어졌습니다. 지금 일반 CSV는 틀린 칸만 뺍니다. AI 계획은 맞았는데 엔진 규칙이 틀린 사례입니다. (#50)

**B6. "0건"과 "없는 대상"을 구분하나요?**
없는 부서나 오타(P99)는 오류로 처리하고 가능한 값 목록을 보여줍니다. 실제 0건이면 정상 결과 0을 보여줍니다. 처음에는 둘 다 "계산할 수 없습니다"였습니다. (#15)

**B7. 배포에서만 생긴 문제는 없었나요?**
로컬은 정상인데 배포 앱에서만 "업무 파일이 필요합니다" 오류가 났습니다. 새 코드를 받으면서 캐시에 남은 옛 데이터를 엔진이 못 알아본 게 원인이었습니다. 데이터에 구조 버전을 붙여 버전이 다르면 다시 불러오라고 안내하게 고쳤고, 배포 상황을 테스트로 재현해 두었습니다. (#28)

**B8. 에이전트 정답률(34/34)은 어떻게 채점했나요?**
실제 Gemini로 질문을 돌리고, 스크립트가 승인한 뒤 결과 표의 숫자만 봅니다. AI가 쓴 문장은 채점하지 않습니다. 순위 질문은 정답이 유일한 1위여야 정답입니다. API 한도 초과는 오답이 아니라 "측정 못 함"으로 따로 셉니다. (#13, #43)

**B9. AI가 정답을 미리 볼 수는 없나요?**
정답 파일은 에이전트 실행이 끝난 뒤에만 엽니다. 정답 파일 없이도 실행 단계가 도는지 테스트로 확인했고, 정답 값은 코드에 쓰지 않습니다. (#13)

**B10. 정해진 질문에만 맞춘 것 아닌가요?**
바꿔 말한 질문, 답하면 안 되는 질문, 다른 업종 CSV 질문, 결과를 보기 전에 미리 만든 질문 묶음을 따로 둡니다. 이 채점에서 AI가 없는 정보를 다른 지표로 바꿔치기하는 실수를 찾아 에이전트 담당에게 넘겼고, 이후 차단 기능이 들어갔습니다. (#24, #32, #52 → #22, #25, #37)

- 34/34는 **우리가 정한 질문 묶음 기준**입니다. "100% 정확"이라고 말하지 않습니다.
- 처음 보는 구조의 CSV는 더 낮습니다. 다른 구조 CSV 묶음(schema)에서 답할 수 있는 질문 17개 중 8개 정답, 답하면 안 되는 질문 8개는 모두 거절했습니다(2026-11-24, #50 머지 전 측정).

- 모르는 건 "지금은 지원하지 않습니다"로 답하고, 계획은 "다음 단계"로 구분합니다.
