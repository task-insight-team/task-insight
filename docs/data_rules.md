# 데이터 규칙 (전처리 규칙 · 지원 분석 목록)

팀 합의 없이 바꾸지 않습니다. 코드 기준: `contracts.py`, `engine/loader.py`, `engine/tools.py`
데이터 설명: `docs/kafe_data_dictionary.md` (가상 제조기업 한빛센서텍, 기준일 2026-11-19)

## 1. 올릴 수 있는 파일

| 종류 | 인식 기준 | 예시 |
|---|---|---|
| 업무 (tasks) | `task_id` 등 업무 컬럼 | `data/kafe/tasks.csv` (150행) |
| 직원 (employees) | `employee_id`, `department` 등 | `data/kafe/employees.csv` (50행) |
| 프로젝트 (projects) | `project_id`, `budget` 등 | `data/kafe/projects.csv` (10행) |
| 일반 CSV | 위에 해당하지 않음 | 과제 `data/sample.csv` |

- 표준 파일로 인식하려면 ID 컬럼(`task_id`·`employee_id`·`project_id`)이 있고, 그 표 컬럼의 **절반 이상**이 있어야 합니다. 몇 개만 겹치는 파일(예: `employee_id, department, salary`)은 일반 CSV로 봅니다.

- 표준 파일은 종류마다 하나씩. 업무 파일이 있어야 직원·프로젝트를 결합합니다.
- 표준 파일과 일반 CSV는 함께 올릴 수 없고, 일반 CSV는 한 번에 하나만 분석합니다.
- 업무 파일만 올려도 분석할 수 있지만, 부서별 분석에는 직원 파일이, 예산 분석에는 세 파일이 모두 필요합니다.

| 상황 | 처리 | 코드 |
|---|---|---|
| 빈 파일 / 헤더만 있음 | 거부 | `empty_file` / `no_rows` |
| 10MB 초과 / 100,000행 초과 | 거부 | `too_large` / `too_many_rows` |
| UTF-8·CP949 모두 아님 | 거부 | `encoding` |
| 같은 헤더 중복, `_`로 시작하는 헤더 | 거부 | `duplicate_headers` / `reserved_header` |
| 표준 파일인데 필수 컬럼 없음 | 거부, 없는 컬럼 안내 | `missing_columns` |
| 꼭 있어야 할 값이 빈칸 (ID·분류·시작일·상태·MH 등) | 경고 + 행 번호, **계산에서 제외** | `missing_values` |
| 날짜가 YYYY-MM-DD 아님 | 경고 + 행 번호, 계산에서 제외 | `invalid_date` |
| 숫자 칸에 N/A·없음 등 / 음수 | 경고 + 행 번호, 계산에서 제외 | `invalid_number` / `negative_number` |
| 상태·우선순위가 허용값 아님 | 경고 + 행 번호, 계산에서 제외 | `invalid_value` |
| **담당자·기한 빈칸** | 경고, **값을 그대로 두고 '확인 필요'로 표시** (담당자 빈칸은 부서 '미배정') | `needs_check` |
| 기한 < 시작일 / 완료인데 완료일 없음 / 완료일 있는데 미완료 | 경고 (계산에는 포함) | `due_before_start` / `done_without_date` / `date_without_done` |
| 부적합 대응인데 문제유형 없음 | 경고 | `issue_type_missing` |
| 미완료 업무의 완료일 빈칸, 부적합 대응 외 업무의 문제유형 빈칸 | **정상 (구조적 공백)**, 참고로만 표시 | `structural_blank` |
| 완전 중복 행 | 경고, 사용자가 확인하면 첫 행만 남기고 제거 | `duplicate_rows` |
| ID 같고 내용 다름 | 경고 (자동 처리 안 함) | `duplicate_id` |

허용값: 업무 상태 `미착수·진행중·완료·보류`, 프로젝트 상태 `진행중·완료·보류`, 우선순위 `높음·중간·낮음`
### 일반 CSV에서만 하는 처리

| 상황 | 처리 | 코드 |
|---|---|---|
| 구분자가 쉼표가 아님 (세미콜론·탭·세로줄) | 첫 줄을 보고 자동 인식 | - |
| 줄 끝 쉼표로 생긴 이름 없는 빈 컬럼 | 버림 | - |
| 값 절반 이상이 날짜 (`2026/01/05`, `2026.1.5`, `2026-01-05 13:45`) | `YYYY-MM-DD`로 맞춤. 월 표기(`2026.01`)는 `YYYY-MM` | `date_normalized` (참고) |
| 연도가 뒤에 오는 날짜 (`01/15/2026 10:00`, `15.01.2026`) | 13 이상인 쪽을 일로 보고 `YYYY-MM-DD`로 맞춤. 모두 12 이하라 월/일 순서를 알 수 없으면 **바꾸지 않고** 글자로 둠 | `date_normalized` / `date_ambiguous` (참고) |
| 날짜 컬럼에 날짜로 읽을 수 없는 값 (`2026-02-30`, `모름`, `20260210`) | 경고 + 행 번호, **그 칸만** 빈칸으로 보고 날짜를 쓰는 계산(월별 묶음·기간 비교·날짜 필터)에서 제외. 같은 행의 다른 컬럼은 그대로 씀 | `invalid_date` |
| 숫자 앞뒤 단위 기호 (`₩1,200`, `1,200원`, `$15`, `12.5%`) | 기호를 빼고 숫자로 읽음 | `unit_removed` (참고) |
| 앞자리 0 코드 (`00123`) | 숫자로 바꾸지 않고 글자로 둠 | - |
| 값 절반 이상이 숫자인 컬럼의 숫자 아닌 값 (`-`, `(300)`, `A/5 21171`) | 경고 + 행 번호, **그 칸만** 빈칸으로 보고 그 컬럼 계산에서 제외. 같은 행의 다른 컬럼은 그대로 씀 | `invalid_number` |

일반 CSV는 **칸 단위**로 제외합니다 (2026-11-24 변경, `DATASET_VERSION` 2). 행 단위로 빼면 숫자·글자가 섞인 다른 컬럼(예: 티켓 번호) 때문에 상관없는 컬럼의 평균이 틀어지기 때문입니다 (공개 벤치마크 DABench의 승객 데이터에서 평균 운임 34.65 → 30.09로 확인). 업무 표준 표(업무·직원·프로젝트)는 지금처럼 **행 단위**로 제외합니다.

원본 파일과 원본 DataFrame은 바꾸지 않습니다. `clean()`은 복사본을 만들고 처리 전후 행 수를 돌려줍니다.

## 3. 결합 규칙 (Step 5 확장 ②)

- 업무 → 직원: `assignee_id = employee_id`, 다대일. 업무의 **부서는 담당자의 부서**입니다.
- 업무 → 프로젝트: `project_id`, 다대일. 프로젝트 유형·주관부서·상태만 붙입니다.
- **결합 후 행 수가 업무 행 수와 같아야 합니다.** 다르면 결합 결과를 쓰지 않습니다.
- 직원·프로젝트 표에 ID 중복이 있으면 결합하지 않습니다 (행이 늘어나기 때문).
- 직원·프로젝트 표에 없는 ID는 경고 (부서 '미확인').
- **예산은 업무 행에 붙이지 않습니다.** 붙인 뒤 더하면 7.03억이 109.03억으로 부풀려집니다. 예산은 프로젝트 표에서 프로젝트당 한 번만 씁니다.

## 4. 계산 기준

| 항목 | 정의 |
|---|---|
| 기준일 | 항상 입력으로 받음 (kafe 데이터는 2026-11-19). 코드에서 오늘 날짜를 쓰지 않음 |
| 미완료 | 상태 ≠ 완료 (미착수·진행중·보류) |
| 기한 초과 | 미완료 그리고 기한 < 기준일. 기한 당일은 초과 아님. 기한 빈칸은 판정 불가로 제외 |
| 완료율 | 완료 건수 / 전체 건수 × 100 (건수 기준) |
| 초과MH | 업무별 max(실적MH − 계획MH, 0)의 합. 미완료 업무의 남은 계획이 다른 업무의 초과를 상쇄하지 않음 |
| 초과 투입 업무 | 완료: 실적 > 계획 × 1.2 / 미완료: 실적 > 계획 |
| 실적 인건비 | 실적MH × 담당자 시간당 인건비 (추정, 현재 단가 소급) |
| 비용 초과율 | (실적 인건비 + 실적 비인건비) / 예산 × 100 − 100. 기준일까지 누적이며 완료 시점 예측이 아님 |
| 반복 문제 | 같은 문제유형이 N건(기본 2) 이상. 업무명 같은 자유 텍스트로 판단하지 않음 |
| 증감률 | (이번 − 이전) / 이전 × 100. 이전 값이 0이면 계산하지 않고 사유 표시 |
| 반올림 | 소수 둘째 자리, 사사오입 |

주의: 실적MH는 기준일까지 **누적값**이라 주당 가용시간과 직접 비교하면 안 됩니다 (과부하 판단 불가).

## 5. 지원하는 분석 (도구 10개)

| 도구 | 하는 일 | 필요한 파일 |
|---|---|---|
| aggregate | 합계·평균·개수·**최댓값·최솟값**, 그룹별, 조건 필터, 정렬, 상위 N, **월별 묶음(`period=month`)**, **곱한 값 집계(`multiply_by`, 예: 재고금액 = 수량×단가)** | 모든 CSV |
| calculate_ratio | **비율(%)**: 그룹별 비중(`share`), 컬럼 합계끼리 비율(`column_ratio`, 예: 불량률), 조건에 맞는 행 비율(`condition_rate`, 예: 처리완료 비율). 그룹별·조건·월별. `column_ratio`는 `percent=false`로 ×100 없는 나눗셈(예: 판매 단가 = 매출÷판매량) | 모든 CSV |
| compare_periods | 두 달 비교 (증감, 증감률), 그룹별 | 날짜·월 컬럼이 있는 CSV |
| count_overdue_tasks | 기한 초과 미완료 업무 수와 목록, 그룹별, **부서·프로젝트 조건** | 업무 (부서 조건은 +직원) |
| summarize_by_category | 범주별 전체·완료·미완료·상태별·완료율, 부서별이면 인원·1인당 미완료 (조건이 있으면 인원 제외), **부서·프로젝트 조건** | 업무 (+직원) |
| calculate_completion_rate | 완료율, 그룹별 (낮은 순), **부서·프로젝트 조건** | 업무 (부서 조건은 +직원) |
| find_recurring_issues | 반복된 문제유형, 관련 프로젝트·업무·부서 | 업무 |
| mh_overrun | 계획 대비 실적 MH 초과, 초과 투입 업무 수 | 업무 |
| cost_vs_budget | 프로젝트별 예산 대비 실적 비용, 비용 초과율 | 업무 + 직원 + 프로젝트 |
| check_missing_data | 확인 필요 누락 데이터 목록 (구조적 공백과 구분) | 업무 |

### 월별 묶음 · 비율 · 컬럼끼리 비교 · 계산 컬럼

- **월별 묶음**: `period="month"`면 `group_by`의 날짜 컬럼(날짜 형식 또는 `YYYY-MM-DD`·`YYYY-MM` 글자)을 `YYYY-MM`으로 바꿔 묶는다. 결과 컬럼 이름은 `완료일(월)`처럼 표시. group_by에 날짜 컬럼이 없으면 오류. 원본 표는 바꾸지 않는다 (표 구조 변경 아님 → `DATASET_VERSION` 그대로)
- **비중(share)**: 그룹 합계(값 컬럼이 없으면 건수) ÷ 전체 합계 × 100. group_by 필수. 대표값(value)은 없고 rows[0]이 가장 큰 그룹
- **컬럼 비율(column_ratio)**: 합계(분자) ÷ 합계(분모) × 100 (행별 비율의 평균이 아님). 분자·분모 중 빈칸인 행은 뺀다. 분모 합계가 0인 그룹은 빈칸(계산 불가), 전체 분모가 0이면 오류
- **조건 비율(condition_rate)**: `condition`에 맞는 행 수 ÷ 전체 행 수 × 100. `filters`는 분자·분모 모두의 범위. 업무 데이터에서 `상태 == 완료` 조건 비율은 완료율 도구와 같은 값
- **곱한 값 집계(`multiply_by`)**: 행마다 `value_column × multiply_by`를 계산한 뒤 합계·평균·최댓값·최솟값을 구한다 (예: 창고별 재고금액 = 합계(수량×단가)). 두 컬럼 모두 숫자여야 하고, 둘 중 하나라도 빈칸인 행은 뺀다. 결과 이름은 `합계(수량×단가)`, basis에 계산식 표시. `count`와 함께 오면 오류. 원본 표에는 컬럼을 추가하지 않는다 (복사본에서 계산)
- **×100 없는 나눗셈(`percent=false`)**: `column_ratio`에서 합계(분자) ÷ 합계(분모)를 그대로 쓴다 (예: 지역별 판매 단가 = 합계(매출) ÷ 합계(판매량), 행별 단가의 평균이 아님). 단위는 빈칸, 결과 이름은 `값(revenue÷units)`. `share`·`condition_rate`에 `percent=false`가 오면 오류 (비중·조건 비율은 항상 %)
- **컬럼끼리 비교**: 필터에 `compare_column`을 주면 값 대신 같은 행의 다른 컬럼과 비교 (예: `수량 < 안전재고`). 숫자끼리·날짜끼리만 크기 비교, 글자끼리는 `==`·`!=`만. 한쪽이 빈칸인 행은 조건에 맞지 않는 것으로 본다

### 조건(필터) 결과 구분

| 상황 | 결과 |
|---|---|
| 데이터에 없는 대상 (없는 부서 `인사`, 오타 `P99`) | **오류** + 가능한 값 목록 (`'부서'에 '인사' 값이 없습니다. 가능한 값: …`) |
| 대상은 맞는데 조건에 맞는 행이 0개 (P01 미완료, 영업+P05) | **정상 결과 0** (개수·합계 0, 목록·표는 빈 행). 평균·완료율은 분모가 0이라 "0건이라 계산할 수 없습니다" |
| 날짜·숫자 비교 (`기한 == 2030-01-01`, `계획MH > 999`) | 값 확인 안 함. 맞는 행이 없으면 정상 0 |
| `품질팀`·`품질부` | 데이터에 있는 `품질`로 맞춤 |

- 확인 대상: `aggregate` 필터의 `==`·`!=`·`in`, 그리고 `count_overdue_tasks`·`summarize_by_category`·`calculate_completion_rate`의 `department`·`project_id`
- 값 확인은 조건을 적용하기 전 전체 데이터로 한다. 각각 있는 대상의 조합이 0건이면 '없는 대상'이 아니라 0건

## 6. 지원하지 않는 분석

- 자유 Python/SQL 실행, 위 10개 외의 계산
- 임의 계산식으로 새 컬럼 만들기 (세 컬럼 이상, 더하기·빼기, 행별 나눗셈 등). 지원하는 것은 두 컬럼 곱의 집계(`aggregate` `multiply_by`)와 합계끼리 나눗셈(`calculate_ratio` `column_ratio`, % 또는 `percent=false`)뿐
- 원인 추정, 위험도 판단, 완료 시점·비용 예측 (상관관계를 인과로 단정하지 않음)
- 주차별 과부하 분석 (시간 기록 데이터가 없음)
- 업무명·프로젝트명 같은 자유 텍스트의 의미 분석
- 주·분기 단위 비교 (현재는 월 단위만)
- 표준 3개 표 외의 파일 결합
