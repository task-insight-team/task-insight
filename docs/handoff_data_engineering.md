## 2. 발표에서 말하면 안 되는 것 (직접 시험해서 확인함)

**① "Task Insight는 중복 합산을 막는다"를 일반화하지 말 것**
- 막는 것: 업무·직원·프로젝트 표를 **붙일 때**의 예산 중복 (7.03억 → 109.03억).
- 못 막는 것: **이미 합쳐진** 한 장짜리 CSV. 2026-11-25에 main 엔진으로 직접 시험했습니다. 회식 2건(50만·30만)을 참석자 5명 행에 회식비 전체로 적은 CSV를 넣고 합계를 내니, 실제 80만 원이 **210만 원**으로 나왔고 경고도 없었습니다.
- 안전한 표현: "회사 데이터는 표가 나뉘어 있고, 표를 붙일 때 생기는 이 실수를 엔진 규칙으로 막았다." 다른 데이터에는 "도메인별 계산 규칙을 추가하는 것이 다음 단계"라고 말합니다.

**② 34/34를 "정확도 100%"로 말하지 말 것**
우리가 정한 질문 묶음 기준입니다. 처음 보는 구조의 CSV는 위 1번 표처럼 더 낮습니다.

**③ 비유 예시는 실제 사건이 아님**
슬라이드 2의 수치는 가상 데이터로 만든 예시이고, 회식비·편의점 비유도 지어낸 장면입니다. "이런 일이 생길 수 있다"로 말하고, "실제로 사고가 났다"고 말하지 않습니다.

## 3. 발표 소재 (PR에는 결과만 있고 이야기는 없는 것)

**① AI는 맞았는데 엔진이 틀렸다 (#50)**
- 공개 벤치마크의 승객 데이터에서 "평균 운임"을 물었을 때, LLM은 계획을 맞게 세웠는데 결과가 34.65가 아니라 30.09로 나왔습니다.
- 원인은 엔진이었습니다. 형식 오류가 있으면 행 전체를 빼는 규칙 때문에, 티켓 번호 칸 오류로 상관없는 운임 값까지 빠졌습니다.
- 메시지: "AI만 의심하면 안 된다. 계산 엔진도 테스트로 검증해야 한다." 슬라이드 7(ITERATION)에 넣기 좋습니다.

**② 데이터 담당이 만든 채점이 AI의 조용한 실수를 잡았다**
- #24 채점: 상품 컬럼이 없는 과제 sample.csv에 "상품별 매출은?"을 묻자 AI가 전체 매출을 대신 계산했습니다. 과제 통과 기준 문장 그대로였습니다.
- #32 채점: 다른 업종 데이터에서 지표 바꿔치기 4건이 나왔습니다(비중 → 합계, 재고 금액 → 수량 등).
- 에이전트 담당에게 넘겨 #22, #25, #37로 고쳤습니다. 지금은 답하면 안 되는 질문을 LLM 호출 없이 막습니다(4/4, Gemini 0회).
- 메시지: 역할을 나눈 팀이 서로의 결과를 검증하는 구조.

**③ 슬라이드 2 "왜"를 와닿게 하는 방법 (발표자와 논의한 내용)**
- 현상(7.03억 → 109.03억)에서 멈추지 말고 **잘못된 결정**까지 보여주기. 순서: 누구나 하는 상황 → 숫자가 틀려 보이지 않음 → 잘못된 결정 → AI에게 물으면 더 빠르고 자신 있게 틀림.
- 한 프로젝트로 보여주면 더 직관적: P01 예산 0.88억 × 업무 18건 = 15.84억.
- 청중용 비유 후보 (숫자는 계산 확인함):
  - 부서 회식비: 회식 1건 50만 원을 참석자 10명 행에 붙여 합하면 500만 원 → "회식비 과다"로 감사 대상
  - 여행 경비 정산: 숙소비 40만 원을 4명 행에 붙여 합하면 160만 원 → 친구에게 4배 청구
  - 편의점 발주: 발주서 총액(50만·30만)을 품목 5줄에 붙여 합하면 80만 원 → 210만 원
- 추천: 업무 주제와 이어지는 회식비. 첫 멘트로는 여행 정산.
