## 세 곳 한눈에 비교 (각 보고서 5절 요약)
| | WrenAI | agno dash | InfiAgent-DABench |
|---|---|---|---|
| 우리 원칙과 충돌하는 점 | LLM이 자유 SQL 작성 | LLM이 SQL 직접 작성·즉시 실행, 사람 승인 없음, 안전을 프롬프트에 의존 | LLM이 파이썬 코드를 써서 실행(숫자를 LLM 경로로 생성), 채점 전 LLM 재포맷 |
| 가져올 만한 아이디어 | 컬럼 의미 사전(MDL 축소판), 기본 조건 누락 시 실행 거부(fail-closed), 증거(evidence) 표시, 되묻기 흐름, 사전 유무 A/B 평가 | 컬럼 의미 사전 주입, 승인된 계획 저장 형식, 평가 분류(accuracy·routing·governance), 개선 루프의 안전한 형태 | 질문 레코드 스키마(level·concepts·format), 하위 답 이름-값 분리 채점, 지표 3종 구분 |
| 가져오면 안 되는 것 | 상용 영역 기능, 상표("Wren"), 임베딩 검색을 필수 경로로 | SQL 직접 실행 구조 전체, 승인 없는 즉시 실행, 숫자를 문장에 직접 쓰는 지시 | **데이터(질문·정답·CSV) 복사·재배포**, 상용 시연·학습에 쓰기 |
| 코드 복사 | 폴더별 Apache 조건 충족 시 가능(권장은 개념 이식) | Apache 조건 충족 시 가능(권장은 새로 구현) | 권장하지 않음 |
| 가장 큰 한계 | Rust·대부분 Python 미열람, 평가 점수 없음, CSV 업로드는 주 타깃 아님 | agno 내부·평가 점수 확인 못 함 | 파이프라인 일부만 키워드로 확인 |

## 이 분석을 어떻게 만들었나 (한계 포함)
- 보고서는 Claude 서브에이전트(Sonnet) 3개가 저장소 하나씩 **읽기 전용**으로 분석해 작성했습니다. 코드는 실행·설치·빌드하지 않았습니다.
- 우리 코드를 읽지 않고 쓴 부분(각 보고서 5절의 "적용처")은 **개념 수준 제안**이며 실제 모듈명은 팀이 맞춰야 합니다.
- 보고서가 스스로 "확인 못 함"으로 표시한 항목이 각 6절에 있습니다. 추측으로 채우지 않았습니다.
- 통합 담당이 직접 다시 확인한 것(2026-11-24):
  - 세 저장소의 LICENSE 머리말(Apache 2.0 ×2, WrenAI는 경로별 라이선스 지도 포함)과 WrenAI의 AGPL "향후 모듈용" 문구
  - InfiAgent README의 데이터 라이선스 배지 `CC By NC 4.0` (10행)
  - DABench 질문 257줄, 정답 257줄, CSV 68개(문서에 쓰인 400개·72개와 다름, 이유는 확인 못 함)
  - WrenAI 분석 커밋의 날짜(2026-11-23)
- 직접 확인하지 않은 것: 보고서의 나머지 서술, 보고서 7절 검증 명령 전부를 제가 실행해 본 것은 아닙니다. 아래 방법으로 팀원이 확인해 주세요.

## 검증하는 방법
1. 저장소 3곳을 같은 커밋으로 받습니다 (코드는 실행하지 않습니다).
   ```powershell
   powershell -File docs\benchmark\fetch.ps1            # 3곳 모두 (임시 폴더 ti-bench)
   powershell -File docs\benchmark\fetch.ps1 -Only dash  # agno dash만 (가장 작음)
   ```
   스크립트가 받은 커밋과 위 표의 커밋이 같으면 `일치`라고 표시합니다.
2. 각 보고서 맨 끝 "7. 검증 방법"의 PowerShell 명령을 그대로 실행하고, 적힌 기대 결과와 비교합니다.
3. 다르거나 확인되지 않는 주장이 있으면 이슈나 PR 코멘트로 알려 주세요. 보고서를 고치겠습니다.
