## A. 동기와 차별점

### 1. 왜 조선(군함) 이야기로 시작했나요? 조선 데이터로 검증했나요?
**답:** 건조 물량이 급증하면 공수, 공급, 일정이 동시에 움직이는 공정관리 문제가 커진다는 점에서 출발했습니다. 기사는 급증 수치를, 영문 보고서는 미국 조선소의 투입 공수 5.4배 확대 계획 같은 병목의 단서를 줍니다. 다만 병목이라는 해석은 저희 정리입니다. 조선 데이터로는 검증하지 않았고, 같은 분석 구조(기한 초과, 부서별 편중, 공수 초과, 비용 초과)가 가상 제조 데이터에서 정답과 일치하는 것까지만 확인했습니다.
**말하지 말 것:** "조선소의 병목을 해결한다." 기사의 톤수는 산출 지표이고 집계 기준이 공개되지 않았다는 한계도 함께 말한다. 방산 데이터는 보안 문제가 있어 공개 가능한 민수·가상 데이터로 시작한다고 답한다.

### 2. 그냥 ChatGPT·Gemini에 CSV를 올리면 되지 않나요?
**답:** 범용 AI도 CSV를 분석합니다. 차이는 "어떤 기준으로 계산했는지 확인할 수 있는가"입니다. 저희는 AI가 분석 계획만 세우고, 실제 숫자는 미리 정의된 Python 계산 도구가 냅니다. 사용자는 계산 전에 계획(계산식, 조건)을 보고 승인하고, 승인한 계획 그대로만 실행됩니다.
**말하지 말 것:** "항상 같은 결과." 계산은 결정적이지만 Gemini가 세우는 계획은 같은 질문에도 달라질 수 있어서 재현성은 "승인한 계획 기준"으로 말한다. 범용 AI와의 정확도 비교 실험은 하지 않았다.

### 3. 엑셀 피벗이나 BI 도구보다 나은 점은? 비교해 봤나요?
**답:** 정량 비교는 하지 못했습니다. 처음 계획에 "정보를 얻는 단계 수와 정확성" 비교가 있었는데, 정확성은 정답 7개를 엑셀 풀이와 함께 기록했지만 단계 수는 측정하지 않았습니다. 차별점은 세 가지입니다. 표를 합칠 때 숫자가 부풀지 않는 결합 규칙, 계산식을 실행 전에 확인하는 승인, 지원하지 않는 질문을 솔직히 거절하는 점입니다. 엑셀로도 가능하지만 표 여러 개를 붙여 합계를 내다 보면 숫자가 부풀어도 티가 나지 않는다는 점을 규칙으로 막았습니다.
**말하지 말 것:** "더 빠르다"처럼 측정하지 않은 주장.

## B. AI 에이전트

### 4. AI 에이전트라는데 AI가 실제로 하는 일은?
**답:** AI는 자연어 질문을 해석해 데이터 구조와 사용 가능한 계산 도구를 보고 분석 계획을 세웁니다. 그 계획을 코드가 다시 검사하고, 사용자가 승인하면 Python 엔진이 계산합니다. 결과 설명문도 AI가 아니라 계산 결과를 템플릿에 채워 만듭니다. AI는 계산하지 않고, 목적을 이해해 도구와 조건을 고르는 역할까지입니다.
**말하지 말 것:** "AI가 결과를 해석해 준다." 초기 기획에는 있었지만 실제로는 빼고 Python 템플릿으로 바꿨다.

### 5. 환각은 어떻게 해결했나요?
**답:** 완전히 없앴다고 말하기는 어렵고, 환각이 최종 숫자에 들어가지 못하게 구조를 만들었습니다. 화면의 숫자·표·차트·설명문은 모두 같은 계산 결과에서 나옵니다. 데이터에 없는 정보를 묻거나 지원하지 않는 계산이면 비슷한 다른 분석으로 바꿔 답하지 않고 "지원 불가"와 이유를 보여 줍니다. 다만 AI가 질문 의도를 잘못 해석한 계획은 나올 수 있어서, 코드 검증과 사용자 승인으로 보완합니다.
**말하지 말 것:** "환각을 없앴다", "계획 검증이 모든 오류를 잡는다."

### 6. LLM이 Python·SQL을 직접 만들게 하면 더 다양하게 답하지 않나요?
**답:** 맞습니다. 하지만 생성된 코드가 잘못된 기준으로 집계하거나, 표를 합치면서 숫자가 부풀거나, 임의 코드 실행의 보안 문제가 생길 수 있습니다. 저희 시연 데이터에서도 단순 결합하면 예산이 15배 넘게 부풀었습니다. 그래서 자유도보다 신뢰성과 실행 통제를 택했고, 팀이 정의하고 테스트한 도구 10개 안에서만 AI가 고르게 했습니다. 앞으로는 검증된 도구를 늘려 범위를 넓히는 방향입니다.
**말하지 말 것:** 도구를 6개나 12개로 말하는 것(엔진 도구 10개, 에이전트 전용 2개는 계산하지 않음).

### 7. 승인 절차가 번거롭지 않나요? 완전 자동이 낫지 않나요?
**답:** 같은 질문도 분모나 포함 대상에 따라 결과가 달라집니다. AI가 해석한 분석이 사용자가 원한 것과 같은지 확인하려고 넣었습니다. 승인 화면에서 계산식을 보고, 승인 뒤 계획이 하나라도 바뀌면 다시 승인을 받습니다. 대가는 클릭 한 번과 호출 지연입니다. 처음 기획에는 없었고, Gemini가 질문 조건을 빠뜨리는 일이 반복돼 추가했습니다.
**말하지 말 것:** 위험도에 따른 자동 실행은 향후 개선이다. 현재는 모든 분석이 승인을 거친다.

### 8. 처음 보는 CSV도 분석되나요?
**답:** 일반 CSV 분석을 넣어 특정 데이터에만 묶이지 않게 했고, 재고·영업·품질 같은 다른 구조의 예시 CSV에서도 같은 흐름이 동작합니다. 다만 질문의 말이 데이터에 없거나 컬럼 의미가 불분명하면 숫자를 내지 않고 되묻거나 지원 불가로 안내합니다. "모든 CSV의 모든 질문"이 아니라 "구조가 달라도 지원하는 분석은 같은 방식으로 수행한다"가 정확합니다.
**숫자:** 다른 구조 CSV 묶음에서 답할 수 있는 질문 17개 중 8개 정답, 틀린 숫자 0(2026-11-24, #50 이전). 답하면 안 되는 질문은 8/8 거절.
**말하지 말 것:** 일반 CSV는 한 번에 파일 하나만 분석한다(여러 파일 결합은 표준 업무·직원·프로젝트 데이터만). 질문의 "고객"과 컬럼 `buyer`처럼 이름이 다른 컬럼을 잇는 기능(PR #44)은 기본 OFF이고 발표에서 켜지 않는다.

### 9. 악성 지시문이 든 CSV나 질문의 조건 누락은요?
**답:** CSV 내용은 지시가 아니라 데이터로 취급합니다. 업무명·프로젝트명 같은 자유 텍스트는 LLM에 보내지 않고, 컬럼 이름과 범주값도 짧은 라벨만 보내며 "무시", "삭제", "ignore" 같은 지시문 표현은 제외합니다. LLM이 무엇을 요청하든 실행되는 것은 허용 목록의 도구뿐입니다. 질문의 조건(부서, 프로젝트, 기간, 지표)이 계획에 빠지면 그 단계를 승인 대상에서 빼고 1회 재계획합니다. 주입 샘플 `data/errors/injection.csv`로 확인합니다.

### 10. Gemini가 느리거나 실패하면요?
**답:** 가짜 답을 만들지 않고 "실패"를 표시합니다. 채점에서는 무료 한도 초과(429)를 오답으로 세지 않고 재시도하며, 그래도 안 되면 "측정 못 함"으로 기록합니다. 발표에서는 앱을 미리 깨워 두고 백업 캡처를 준비했습니다. 평소 질문당 처리 시간은 평균 약 1.4초였습니다(무료 등급 모델, 2026-11-25 측정).

## C. 데이터와 엔진

### 11. 표를 합칠 때 숫자가 부풀지 않게 한 방법은?
**답:** 예산은 업무 행에 붙이지 않고 프로젝트 표에서 프로젝트당 한 번만 씁니다. 업무 → 직원·프로젝트는 다대일로 결합하고, 결합 후 행 수가 업무 행 수(150)와 다르면 결합 결과를 쓰지 않습니다. 직원·프로젝트 표에 ID 중복이 있어도 결합하지 않습니다. 잘못 붙이면 7.03억이 109.03억(15.5배)이 되는 것을 테스트로 고정했습니다.
**말하지 말 것:** 15번의 한계(이미 합쳐진 표).

### 12. 빈칸·오타·날짜·금액 표기·큰 파일은 어떻게 처리하나요?
**답:** 올리자마자 파일별로 검사해 어디가 비었는지 행 번호와 함께 보여 줍니다. 형식 오류 행은 계산에서 빼고 몇 개를 뺐는지 결과 옆에 적으며, 몰래 채우거나 추측하지 않습니다. 담당자·기한 빈칸은 오류가 아니라 "확인 필요"로 표시합니다. `2026.1.5`, `₩1,200`, `12.5%` 같은 표기는 자동으로 맞추고, UTF-8과 CP949를 모두 읽습니다. 파일 하나는 10MB, 10만 행까지이고, 완전히 같은 행은 알려만 주고 사용자가 지울지 정합니다. 엑셀은 CSV로 저장해 올립니다.

### 13. '기한이 지났다'는 언제 기준인가요?
**답:** 기준일을 입력으로 받습니다. 프로그램이 오늘 날짜를 쓰지 않아서 같은 기준일이면 언제 돌려도 같은 답이 나옵니다(시연 데이터 기준일 2026-11-19). 기한 당일은 초과가 아니고, 기한이 빈 업무는 판정 불가로 제외합니다.

### 14. 형식이 틀린 값은 행째 빼나요? 결과가 틀린 적은 없나요?
**답:** 처음에는 행째 뺐고, 그게 문제를 만든 적이 있습니다. 공개 벤치마크 승객 데이터에서 티켓 번호 칸 오류 때문에 운임 평균이 34.65가 아니라 30.09로 나왔습니다. AI 계획은 맞았는데 엔진 규칙이 틀린 사례입니다. 지금 일반 CSV는 틀린 칸만 뺍니다(#50). "AI만 의심하면 안 되고 계산 엔진도 테스트로 검증해야 한다"는 교훈입니다.
**말하지 말 것:** 이 벤치마크 수치는 로컬 실행이라 다른 사람이 재현할 수 없다(데이터 라이선스).

### 15. 우리 회사 데이터를 넣으면 바로 쓸 수 있나요? 중복 합산은 다 막나요?
**답:** 합계, 평균, 월별 추이, 비율 같은 기본 분석은 바로 됩니다. 하지만 중복 합산 방지는 업무·직원·프로젝트 표를 붙일 때의 규칙입니다. 이미 합쳐진 한 장짜리 CSV는 못 막습니다. 직접 시험했을 때, 회식 2건(50만·30만 원)을 참석자 5명 행에 전체 금액으로 적은 CSV의 합계가 실제 80만 원이 아니라 210만 원으로 나왔고 경고도 없었습니다. 회사별 계산 규칙 추가가 다음 단계입니다.
**말하지 말 것:** "Task Insight는 중복 합산을 막는다"를 일반화하는 것. 안전한 표현은 "표가 나뉜 회사 데이터를 붙일 때 생기는 실수를 규칙으로 막았다."

### 16. 배포 환경에서만 생긴 문제는 없었나요?
**답:** 있었습니다. 로컬은 정상인데 배포 앱에서만 "업무 파일이 필요합니다" 오류가 났습니다. 새 코드를 받으면서 캐시에 남은 옛 데이터를 엔진이 못 알아본 것이 원인이었습니다. 데이터에 구조 버전을 붙여 버전이 다르면 다시 불러오라고 안내하게 고쳤고, 배포 상황을 테스트로 재현해 두었습니다(#28). 엔진 구조가 바뀌는 머지가 또 있으면 배포 앱 Reboot이 필요합니다(배포 계정은 AI 에이전트 담당).

## D. 검증

### 17. 결과가 정확하다는 것은 어떻게 검증했나요?
**답:** 계산 엔진 검증과 에이전트 검증을 나눴습니다. 자동화 테스트 565건이 통과했고(11건은 실제 Gemini를 부르는 테스트라 평소엔 건너뜀), 기준 질문 7개를 pandas로 따로 계산해 모두 일치했으며 그중 5개는 엑셀로도 확인했습니다(Q2·Q4는 결합이 필요해 엑셀 미검증). 에이전트는 실제 Gemini로 질문부터 실행까지 돌려 정답과 비교하는 채점을 합니다. 우리 질문 묶음 기준 34/34, 시연 질문 3회 반복 15/15였습니다.
**말하지 말 것:** 565건을 "AI 답변 정확도"라고 하는 것. 대부분 계산·검증 로직의 단위 테스트다. 34/34를 "정확도 100%"라고 하는 것. 우리가 정한 질문 묶음 기준이며, 처음 보는 구조의 CSV는 더 낮다(질문 8의 숫자).

### 18. 에이전트 정답률(34/34)은 어떻게 채점했나요?
**답:** 실제 Gemini로 질문을 돌리고 스크립트가 승인한 뒤 결과 표의 숫자만 봅니다. AI가 쓴 문장은 채점하지 않습니다. 순위 질문은 정답이 유일한 1위여야 정답이고, API 한도 초과는 오답이 아니라 "측정 못 함"으로 따로 셉니다. 같은 질문도 Gemini 계획이 흔들릴 수 있어 반복 측정(`--repeat`)도 지원합니다.

### 19. AI가 정답을 미리 보거나 정해진 질문에만 맞춘 것 아닌가요?
**답:** 정답 파일은 에이전트 실행이 끝난 뒤에만 열고 정답 값은 코드에 쓰지 않으며, 정답 파일 없이도 실행 단계가 도는 것을 테스트로 확인합니다. 정해진 질문에만 맞추지 않았는지 보려고 바꿔 말한 질문, 답하면 안 되는 질문, 다른 업종 CSV 질문, 결과를 보기 전에 미리 만든 질문 묶음(holdout)을 따로 둡니다. 이 채점에서 AI가 없는 정보를 다른 지표로 바꿔치기하는 실수를 찾아 에이전트 담당에게 넘겼고, 그 뒤 차단 기능이 들어갔습니다.

## E. 보안과 범위

### 20. 기업 데이터가 외부 AI로 유출되지 않나요?
**답:** 먼저 시연 데이터는 가상입니다. Gemini에는 원본을 보내지 않고, 사용자의 질문, 컬럼 이름과 형식, 표준 데이터의 부서·상태 같은 범주값과 ID만 보냅니다. 업무명·프로젝트명 같은 자유 텍스트, 숫자 값, 원본 행은 보내지 않고, 일반 CSV는 셀 값을 아예 보내지 않습니다. API 키는 저장소에 없고 배포 환경 Secrets로 관리합니다. 다만 외부 API를 쓰므로 외부로 가는 정보가 전혀 없다고는 할 수 없고, 실제 기업 데이터에는 인증, 접근 권한, 전송 범위와 보존 정책의 추가 설계가 필요합니다.
**말하지 말 것:** "정보가 외부로 전혀 가지 않는다." 질문 문장과 컬럼 이름, 범주값, 직원 ID 같은 값은 간다. 질문에 민감한 내용을 쓰면 그대로 전송된다. Gemini 쪽 데이터 보존·학습 조건은 요금제에 따라 달라서 확인하지 않은 조건을 단정하지 않는다.

### 21. 로그인·저장은 왜 만들지 않았나요? 개인정보는?
**답:** 과제 Step 1과 Step 3(계획 → 승인 → 실행 → 기록)에 집중하려고 Step 2(로그인·저장)를 의도적으로 제외했습니다. 그래서 분석 결과를 저장하지 않고, 업로드 파일은 서버 메모리 캐시(최대 4건)에 한시적으로 남을 수 있습니다. 시연 데이터는 합성이라 개인정보가 없습니다.

## F. 협업과 기여

### 22. AI로 개발했다면 본인이 기여한 부분은?
**답(각자 맡은 부분으로 바꿔 말하기):** 사람이 정한 것은 설계 방향이었습니다. 계산은 코드가 하고, 승인을 거치고, 모르면 거절한다는 판단입니다. 구현은 AI 코딩 도구와 함께 했고 결과는 사람이 검증했습니다. 예를 들어 실제 Gemini로 시험하니 질문의 "고객"을 매장 컬럼으로 해석하는 경우가 있어, 재현 조건으로 정리해 규칙을 넣고 그래도 애매한 경우가 남아 그 기능을 기본 OFF로 두기로 했습니다. 역할은 AI 에이전트(docie-rgb), 데이터 엔지니어링(zslayer-dev), 프론트엔드·시각화(jhwksh), 통합·보고서(victorymankang-dot)입니다.
**말하지 말 것:** 다른 팀원의 작업(계산 엔진, 화면, 채점 도구, 테스트 통합·배포)을 "제가 만들었다"고 말하는 것. 일부 코드를 AI 도구(Claude Code)와 함께 작성했다는 점은 README에 밝혀 두었다.

### 23. 4명이 동시에 개발하며 형식은 어떻게 맞췄나요?
**답:** 첫 PR에서 모듈 간 데이터 형식(`contracts.py`), 엔진, 정답 테스트를 한 번에 올리고 담당별 리뷰를 받았습니다. 이후 형식 변경은 기존 값을 바꾸지 않고 추가만 했고 팀 합의 후 머지했습니다. 엔진 도구가 늘 때마다 에이전트가 따라가는 연동 PR이 필요했습니다(#38→#39, #40→#42). 엔진이 도구 목록을 Gemini용 스키마로 직접 만들어 줘서 도구를 추가하면 AI 쪽 선언이 자동으로 따라갑니다. 폴더 단위 담당과 "main 직접 push 금지, 브랜치 → PR → 테스트 통과 → Squash merge" 규칙으로 병렬 작업이 가능했습니다.

## G. 확장과 한계

### 24. 현업에서는 어떻게 활용할 수 있나요?
**답:** "질문 → 계획 → 승인 → 계산" 구조는 데이터만 바꿔 다른 분야에도 쓸 수 있습니다. 재고·영업·품질 예시 데이터에서 같은 구조로 불량률이나 매출 비중을 계산합니다. 첫 확장 후보는 조선 공정관리이고, 그다음은 생산·품질, 안전보건(EHS), 프로젝트·경영입니다. 예를 들어 안전보건이라면 "기한이 지난 미완료 개선조치는?", "반복해서 나오는 위험요인은?"을 자연어로 묻고 근거와 그래프를 확인하는 방식입니다. 앞으로는 CSV 대신 ERP·MES·DB 연동으로 발전시킬 수 있습니다.
**말하지 말 것:** 조선·안전보건 데이터 적용과 DB·ERP·MES 연동은 향후 계획이다. 실제 시험은 하지 않았다. "이미 된다"가 아니라 "기한 초과·반복 이슈 같은 기존 도구로 다룰 수 있는 형태"라고 말한다.

### 25. 아직 못 하는 것은 무엇인가요?
**답:** 분명한 한계가 있습니다. 한 계획은 서로 독립인 단계 4개까지이고 앞 결과에 따라 달라지는 질문은 지원하지 않습니다. 월 단위 비교만 되고, 시간 기록 데이터가 없어 주차별 과부하 분석도 못 합니다. 인건비는 현재 단가를 소급한 추정이고 비용 초과율은 기준일 누적값입니다. 파일을 올리자마자 문제를 먼저 알려 주는 기능, 원인 추정과 예측도 없습니다. 이미 합쳐진 표의 중복 합산도 아직 막지 못합니다. 로그인·접근 권한도 이번 범위에서 제외했습니다.

## 답변 원칙과 금지 표현

1. 숫자는 맨 위 "확인된 수치" 표의 값만 말합니다. 표에 없으면 "측정하지 않았습니다"라고 답합니다.
2. 한계를 먼저 인정하고 대신 한 일을 말합니다.
3. 모르는 질문은 "그 부분은 확인하지 못했습니다"라고 답하고 근거 위치(문서·PR)를 안내합니다.
4. 말하지 않는 표현: "환각을 없앴다", "정확도 100%", "항상 같은 결과", "중복 합산을 막는다"(일반화), "외부로 전혀 가지 않는다", "조선소 병목을 해결한다", 측정하지 않은 "더 빠르다".
5. 비유(회식비, 여행 경비, 편의점 발주)와 슬라이드의 숫자는 가상 예시이며 실제 사건이 아닙니다.
6. 담당이 아닌 부분은 "그 부분은 ○○ 담당이 더 정확히 답하겠습니다"라고 넘깁니다.
